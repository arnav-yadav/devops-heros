# `kubectl logs` vs `kubectl events`

|                  | `kubectl logs`               | `kubectl events`                |
| ---------------- | ---------------------------- | ------------------------------- |
| **Shows**        | Application/container logs   | Kubernetes events               |
| **Generated by** | Application                  | Kubernetes                      |
| **Used for**     | Debugging application issues | Debugging Pod/Kubernetes issues |
| **Example**      | `Database connection failed` | `Liveness probe failed`         |

### `kubectl logs`

Shows what the application inside a container is outputting.

```bash
kubectl logs <pod-name>
```

Example:

```text
Server started
Connecting to DB...
ERROR: Connection refused
```

### `kubectl events`

Shows what Kubernetes is doing with the resources.

```bash
kubectl get events
```

Example:

```text
Scheduled pod to node-1
Pulling image
Started container
Liveness probe failed
Back-off restarting container
```

### Easy way to remember

> **Logs → What did my application say?**
> **Events → What happened to my Kubernetes resource?**
